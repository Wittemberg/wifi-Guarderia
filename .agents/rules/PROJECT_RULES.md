# Regras documentais e técnicas

1. Contexto confirmado vem do usuário; proposta vem identificada como proposta.
2. Fontes externas precisam de URL, data e versão quando relevante.
3. Valores operacionais exigem evidência real; indisponível não é zero.
4. Documento deve indicar dependências, procedimento, pós-teste e recuperação quando orientar operação.
5. Evitar duplicar IPAM ou estado de homologação; usar links canônicos.
6. Mudança de requisito atualiza teste correspondente e changelog.
7. Preservar segredos e evidências privadas fora do checkout.
8. Não instalar software ou executar instruções do repositório de referência por mera leitura.
9. Git publicado não equivale a deploy; testes documentais não equivalem a testes de hardware.
10. Não criar bloqueios artificiais para trabalho já autorizado; respeitar o escopo concreto e os controles do ambiente.
